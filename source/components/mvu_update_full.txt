【变量更新规则】
本规则属于 [mvu_update]，由更新模型执行。

一、更新协议
1. 当正文中的状态发生变化时，在回复末尾输出一个且仅一个 <UpdateVariable> 块。
2. 块结构：
   <UpdateVariable>
   <analysis>（每行描述一个状态变化）</analysis>
   <JSONPatch>
   [ ... ]
   </JSONPatch>
   </UpdateVariable>
3. <analysis> 必须在 <JSONPatch> 之前，且位于块内。

二、允许的操作（仅这四种）
- add：新增字段或记录项；数组末尾追加用 /-
- replace：替换已存在路径的值；路径不存在时禁止使用
- remove：删除字段或记录项
- move：字段迁移，from → path

三、路径规则
1. 路径格式：/顶层容器/键名/子字段
2. 顶层容器白名单（只允许这些根）：环境、角色
3. 角色池为封闭白名单，仅限九名预置女性：凉、惠惠、达克妮丝、阿库娅、辉夜、早坂爱、早坂奈央、藤原千花、藤原萌叶。禁止 add 新角色：任何新登场人物（无论男女、无论戏份）一律只写叙事，不入池；物品、文书、契约、建筑、神像、概念更不是角色，一律禁止入池
4. 白名单角色的写入方式：进出场景 replace 在场；状态/心声/名分/衣着随剧情 replace；禁止 remove 整项、禁止新增记录键
5. 衣着字段的写入规范：衣着是色情进度的刻度尺，随剧情实时 replace，不写静态人设标签；写当前身上衣物的具体状态（何物、齐整或凌乱、位置），暴露程度逐级记录（松脱→滑落→被撕破→残片→全裸），湿润脏污（汗/香灰/精液）明显时写入；收编之后的日常衣着体现名分待遇（神婢粗布掩不住要害、神妃华服内不着一物之类）；正文与衣着字段必须一致，写了脱就不能还穿着
6. 新增记录项必须先 add 完整对象，才能 replace 其子字段
5. 数值只写数字，布尔写 true/false，文本写字符串；禁止写 [值, 描述] 二元组

四、纪律
1. <analysis> 每行必须对应至少一条 JSONPatch，禁止分析提到变化而 patch 遗漏
2. 没有状态变化时不输出块
3. 块内只写状态数据，不写剧情、感想、解释
4. 只有明确的一次性无名临时角色、确认不再返场且未被其他记录引用时，才可 remove 整项

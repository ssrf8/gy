# 开局页使用说明 · 中元特供·关公

> 交付物：`source/ui/opening-page.html`（自包含，v0.4，TH 前端代码块机制）
> 机制：两步选择 —— ①选守护灵（**开启对应世界书条目 + 关闭另一个**）→ ②选开场白并**切换**。
> **开场白 = SillyTavern 角色卡的「备选开场白」（alternate_greetings）**。点选后聊天首消息真正切换为该开场白（ST 原生 swipe 机制），玩家自由输入开始。

## 0. 渲染机制（v0.4 起，必须理解）

消息里裸写的 `<script>` 在 ST 1.18 中**不会**被可靠执行。酒馆助手（TH 4.8.19）执行消息内 JS 的唯一机制是**「前端代码块」**：

1. `opening-page.html` 本身是一个完整 HTML 文档（`<!DOCTYPE html><html><head>…<body>…`），外层用 markdown 围栏（```` ```html ````）包住，首尾各带 `<!--gg-opening-begin-->` / `<!--gg-opening-end-->` 标记（在围栏**外**）
2. ST 渲染 first_mes → 围栏变成 `<pre><code>`；TH `src/store/iframe_runtimes/message.ts` 扫描聊天里的 `<pre>`，内容含 `html>` / `<head>` / `<body>` 之一（`isFrontend` 判定）→ 包进 `div.TH-render`
3. TH `Render.vue` 把 `Iframe.vue` teleport 进去，生成 `TH-message--{楼层}--{索引}` iframe，内容 = 围栏里的完整文档
4. TH 向该 iframe 注入 `predefine.js`（`src/iframe/predefine.js`）：`window.SillyTavern`（含 `getContext()` shim）、`window.TavernHelper`、以及 `updateWorldbookWith` / `getWorldbook` / `replaceWorldbook` / `getCharWorldbookNames` / `getCurrentMessageId` 等全局函数（`TavernHelper._bind` 解绑注入）

**前置依赖：TH 渲染器需开启**（TH 面板 → 渲染器，默认开启；`render.enabled: true`、`collapse_code_block: 'frontend_only'` 均为默认值）。关闭时页面退化为代码块，不可交互。

## 1. 如何放入角色卡

1. 角色卡编辑器 → **「备选开场白」**里填写你要的开场白正文（写几个显示几个，开局页自动列出）
2. 把 `opening-page.html` 整块内容（`<!--gg-opening-begin-->` 到 `<!--gg-opening-end-->`，**含围栏**）粘贴进 **first_mes** —— 围栏和标记都是文件自带的，直接整块贴
3. first_mes 末尾（end 标记之后）追加一段**给模型看的简短叙事**，例如：
   > 中元夜，{{user}}手中的祖传玉佩忽然发烫，两道虚影浮出——丹凤眼长髯者按刀而立，黑面执鞭者拱手而笑。玉佩在等{{user}}选一位守护灵。人间香火，都认这块玉。

## 2. 世界书条目标题约定（步骤①生效前提）

ST 世界书条目的「标题」= 条目的 **comment（备注）字段**（v2 无顶层 name；TH 视角 `entry.name` 也映射自 comment）。开局页按**标题（comment）包含「关羽」或「赵公明」**来开/关条目：

| 条目标题（comment，必须包含） | 点击「关羽」按钮后 | 点击「赵公明」按钮后 |
|---|---|---|
| `[mvu_plot] 守护灵·关羽` | 启用 ✅ | 禁用 ❌ |
| `[mvu_plot] 守护灵·赵公明` | 禁用 ❌ | 启用 ✅ |

- 守护灵两条目为**常驻蓝灯**（`constant: true`，不靠关键词触发）：开局页只翻转 `enabled`，选中的一条始终注入上下文，模型无需玩家提及名字也持有当前守护灵设定；未选中的一条完全不参与
- 组装脚本已自动写入标题与 constant 配置；手工建条目时务必在「备注」里填上标题、勾选「常驻」
- 条目必须在**当前角色卡绑定**的世界书里（primary 或 additional 均可，自动查找）
- 条目正文写卡阶段补（占位规划见 `source/worldbook/世界书布局.md`）

## 3. 模型上下文保护（推荐正则）

整页 HTML 会进入模型上下文。建议在角色卡加一条正则（`source` 位置）把整块 UI 替换成一行叙事：

- 正则：`/<!--gg-opening-begin-->[\s\S]*?<!--gg-opening-end-->/g`
- 替换文本：`（{{char}}出示祖传玉佩，两道守护灵虚影浮出，等{{user}}选择其一。）`
- 位置：AI 输出（placement 2），替换目标选「提示词」（prompt-only），深度不限

> 依据（2026-08-22 核实）：placement 0（MD_DISPLAY）已废弃禁用，须用 2（AI_OUTPUT）；`maxDepth` 不可设 0（0=仅最新楼，聊天变长后首楼不再剥离）。组装脚本已按此写入，手工配置照此设置。

## 4. 切换后的行为（无自动发送）

- 点击开场白 → 首消息切换为该开场白 → **页面本身消失**（首楼已被替换），玩家在输入框**自由输入**开始故事
- 首消息 swipe 按钮保留：玩家可随时手动切回其他开场白
- 模型侧信息源（开局页不做任何写入）：
  - 已启用的守护灵条目注入上下文 → 模型知道当前守护灵
  - 家族/组织条目已移除（v0.2.1 四家下架）；未来填入时走绿灯关键词激活
  - `玉佩.当前守护灵` 由正常更新链维护
- 开局页**不直接写 MVU 变量**（C10：开局草稿不得绕过正常变量链）

## 5. 能力探测与降级

- 缺酒馆助手或**渲染器未开启**（TH 面板 → 渲染器，默认开启）：页面显示为代码块（围栏原文），按钮不可点 —— 提示安装 TH / 开启渲染器后刷新
- TH 渲染器开启但世界书 API 异常（< v4.8）：步骤①点击后页内报错提示；步骤②（开场白切换）不依赖世界书 API，仍可用
- 角色卡没有备选开场白：步骤②显示「请在角色卡编辑器的「备选开场白」中填写」
- 找不到守护灵条目：步骤①显示「未找到含守护灵条目的世界书（条目标题须包含「关羽」或「赵公明」）」

# 玩法设计 · 中元特供·关公

> 状态：初稿 v0.1 ｜ 日期：2026-08-20
> 本文档是卡面内容的唯一设计权威；字段链变更按 AGENTS.md 同步（账本 ↔ schema ↔ 初始变量 ↔ 世界书布局）。

## 1. 一句话玩法

{{user}} 从祖传玉佩获得守护灵之力，二选一（关羽 / 赵公明），借助其力量行走于四家之间。无宏大世界观，短开局，轻状态。

## 2. 核心机制

### 2.1 选择与切换
- 开局问候简短交代玉佩异变，展示两位守护灵，由 {{user}} 一句话选择
- 选择即生效：选中者的世界书条目开启（绿灯关键词命中），未选中者条目关闭
- 后续 {{user}} 可随时切换；MVU 状态 `玉佩.当前守护灵` 记录当前者，是唯一事实源
- 条目开合是文本驱动的（守护灵名出现在当前消息即激活），无需脚本手动开关
- 守护灵名会在叙述中自然反复出现（对话、显灵、家族供奉），条目随之常开；即使某轮完全没提，`stat_data` 仍携带当前守护灵，模型不会失忆

### 2.2 四家信奉
- 四家（王 / 李 / 张 / 陈，占位名，写卡阶段定稿）条目以家族名开绿灯
- 条目文本不写死神名，只写「虔诚信奉玉佩守护灵」→ 无论玩家如何切换，四家信奉自动跟随当前守护灵，永不矛盾
- 信奉是恒定设定，不做好感度/数值状态，保持简单

## 4. MVU 状态（stat_data）

### 玉佩（核心容器）
| 路径 | 类型 | 默认 | 写入者 | 生命周期 |
|---|---|---|---|---|
| /玉佩/当前守护灵 | string | '' | LLM | 未选为空；玩家选定/切换时 replace |
| /玉佩/显灵状态 | string | '未觉醒' | LLM | 未觉醒 → 苏醒（选定）→ 显灵（关键时刻）|

### 环境 / user
保持通用：日期、时间、地点、氛围 ｜ 状态、位置（写卡阶段如需可增删）。

## 5. 开局流程（简短）

1. 固定问候：<100 字场景（玉佩异动）+ 两位守护灵各一句自我介绍 + 一句询问选择
2. {{user}} 消息含选择（如「我选关羽」）→ 对应条目绿灯开启
3. 首轮生成：守护灵显现 + 四家背景自然带出

示例对话（草稿，写卡阶段润色）：

> **{{char}}**：玉佩在你掌心烫了一下，两道虚影浮出——丹凤眼长髯者按刀而立：「关羽，可护你刀山火海。」金袍执鞭者拱手笑道：「赵公明，保你财源广进。」「小友，选一个吧。」
> **{{user}}**：我选关羽。
> **{{char}}**：虚影合入玉佩，丹凤眼睁开一线。窗外传来梆子声，王家的灯笼一盏盏亮起——今夜起，四家都会供你这块玉。

## 6. 写作红线

- 四家条目不写死神名（写「玉佩守护灵」），信奉跟随当前守护灵
- 不引入宏大世界观：无势力斗争、无天命主线，状态只有玉佩
- 守护灵/家族名须在叙述中自然反复出现，保证绿灯条目常开
- 模型可见文本不含开发注释、装饰性 Markdown

## 7. 开放点（写卡阶段定）

- 四家具体姓名、居住、色调
- 背景是否落「中元节夜晚」（文件夹主题暗示，待定）
- 切换守护灵是否有冷却/代价（默认无，保持简单）
